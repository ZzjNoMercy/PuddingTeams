## 1. 修订后的优先级（P0 → P4）

> 修订理由：PuddingClaw 的 `respond`/continuation token 是私有协议能力，只有一个实现样本时把它
> 抽象成「通用 HITL」是在泛化特例。平台更基础的价值是「manager 派活 → worker 执行 → 进度可见
> → 产物返回 → manager 汇总」这条链在主流 Agent 上跑通。

| 优先级 | 阶段 | 做什么 | 参考 | 完成判据 |
| --- | --- | --- | --- | --- |
| **P0** | 通用无 HITL 主链路加固 | 任意 Agent 的基本协作链：run / continue / cancel / progress / workspace / artifacts / Session 连续性；不依赖任何 HITL 能力 | 方案 §3、§15 | pi + puddingclaw 全流程回归无人工介入 |
| **P1** | 主流 Agent Connector（第二个样本） | 在本地 pi（SDK 型，已完成）之外接入一个主流 coding agent（候选：openclaw / codex / claude code），验证 CLI/ACP/RPC 型 Driver：流式、取消、workspace、observe 收集 | 方案 §8.2、§15.4；ACP <https://agentclientprotocol.com> | 群聊中主流 agent 与 pi/puddingclaw 协同完成任务；observe artifacts 与 git diff 一致 |
| **P2** | Extension 生态最小闭环 | 双宿主 Connector 包（pi `pi install` 可装 + PuddingTeams Driver SPI）；`extension init/validate`；一个声明式 + 两个代码型 Connector；作者文档 | 方案 §9.5、§10.3、§10.4；根目录 `extensions/` | ✅ 已完成；隔离 Extension Host 与社区安装移至延期 backlog |
| **P3** | 可安装产品 + 工作收口 | 先收口项目 Workspace/Session 正确性，再做 npm CLI/Web 单体分发、发行验收与 macOS 桌面包；并行补 Session Goal/责任连续性。Extension Host 仅保留延期待办 | `docs/2026-08-10-P3-可安装产品与项目工作区开发计划.md` | 新机器从零安装到完成一次项目协作；不同项目 Session 不串联；Goal 有负责人、当前状态和完成边界 |
| **P4** | 通用 HITL 重估 | 等第二个主流 Agent 也出现「原 Run 暂停 + 结构化 Interaction + 跨进程 respond」需求时，用两种协议的共同部分设计 PWCP HITL；届时补齐 reject 回送、原子状态迁移、崩溃补偿、重启恢复 | 方案 §6、§7 | 至少两个独立 Driver 实现同一 HITL 抽象 |

### 1.1 Phase 3 安全收口（已完成）

PuddingClaw 专属 HITL 深挖（生产级崩溃补偿、重启恢复、通用抽象）后放到 P4，但已做安全收口：

- ✅ reject 终态释放 session 锁 + 清理加密 continuation token（`runtime.ts` respond 分支；回归测试「安全收口： reject 释放 session 锁并清理 provider state」）；
- ✅ 审批卡 UI 标记「实验」（`interaction-card.tsx`）；
- ✅ 未验证的 Connector 不声明 respond（pi connector `interactionKinds: []`）；
- ⏸️ 留待 P4：reject 回送原 Run（`driver.respond` reject decision 接线）、并发审批的窄竞态（broker.submit 读-检-写非原子）、approved 后 driver 调用失败的卡死恢复、服务端重启重建 activeRuns 锁、question 投影语义（`normalize.ts` 把答案选项塞进 options 强转 scope——目前选分析模型走 manager 文字转述 + continue 的可用路径，不砍）。

## 2. 顺序说明

- **P0 → P1 是主线**：主链路不依赖 HITL；P1 的第二个 Connector 样本是 P2/P4 的共同前提。
- **P2 依赖 P1 的教训**：有了两个真实 Driver 才知道双宿主包的边界画得对不对。
- **P3 产品层已先行收口**：按当前决策，npm CLI/Web 分发与 Electron 暂缓；下一次进入发行线前先做一次产品验收/缺口复核。Extension Host 继续留在发行之后的延期 backlog，不因产品功能完成而自动提前。
- **P4 不设时间**：没有第二个协议样本前不动通用 HITL 抽象。

## 4. 全局约束（开发时随时对照）

方案 §13 的 20 条默认决策，尤其：

- 语义统一、命令名不统一；`continue`/`respond` 不合并（决策 1–3）；
- token/continuation 不进 LLM、浏览器、Session 历史（决策 4）；
- Extension 只拿 `ScopedAgentInvoker`，不碰凭证、不 spawn（决策 15）；
- 无兼容、无历史数据迁移（决策 20）；
- workspace 是项目上下文与默认操作范围；强制权限由各 Agent sandbox/permission mode 或 OS 隔离实施。交付物 push/observe 双轨，不扫描目录猜测（决策 17–19 的修订见 P3 计划 §1.2）。
