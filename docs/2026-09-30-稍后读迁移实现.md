# 稍后读：独立阅读收件箱与 Wiki 来源快照

用户已确认稍后读是独立侧边栏入口，与知识库同级，正式静态路由为 `/read-later`，文章深链使用 `?item=<id>`。首次收藏不要求绑定知识库，也不调用模型。功能从 PuddingClaw 的行为契约迁入 Teams，不依赖其 Python 服务或运行目录，不自动复制历史用户数据。

## 数据与采集

稍后读 HTTP 请求沿用 PuddingClaw 的 Chrome/136 User-Agent、中文 `Accept-Language`、Accept、`gzip, deflate` 与 `Connection: close`；Host 由 Node 按当前 URL 逐跳生成，避免重定向携带旧 Host。该请求配置只在稍后读采集入口覆盖共享网络默认值。请求头一致不代表所有外站都可采集，也不代替站点要求的验证。

HTTP 正文解码优先 BOM，其次响应头和 HTML meta 的 charset。没有可用编码声明的 HTML 先严格尝试 UTF-8，非法 UTF-8 字节回退 Windows-1252，以保留旧版西文网页的重音字符和标点；纯文本不使用此兜底。Word 导出的 `Bulletedlist` 段落若以 Symbol 字体的间隔点作为项目符号，则转成 Markdown 列表，普通正文间隔点和代码保持原样。修复发生在新采集的字节解码与提取阶段，已落盘的乱码版本需要重新采集。

真实微信公众号正文容器 `js_content` 会带有等待客户端排版的初始 `visibility: hidden`。在确认域名为 `mp.weixin.qq.com` 时，正文提取和长度判定忽略该容器自身的初始 visibility；隐藏子块、display:none、hidden/aria-hidden、脚本及其他站点继续按原规则过滤。

代码块提取保留 br 换行、微信 `code-snippet__line` 的逐行布局、空行及缩进，并用足够长的 Markdown fence 保留内容中的反引号。`code-snippet__line-index` 属于行号装饰，不进入正文；空列表项不提取，阅读器也不显示无文本或图片的列表项，避免出现整屏空圆点。

服务端位于 `apps/server/src/read-later/`；状态位于 `<PUDDINGTEAMS_HOME>/state/read-later/`。

- `read-later.sqlite` 保存用户归属的收藏、不可变正文版本、采集任务、操作幂等记录与整理映射。SQLite 事务及有效 URL 唯一索引保证同用户 canonical URL 去重；重复收藏保留现有标题、标签和笔记。
- 原始 URL 单独保留；canonical URL 去除 fragment 和已知跟踪参数，对剩余参数排序。同一操作标识携带不同请求返回冲突。删除过的收藏不会被旧操作标识偷偷重建。
- 阅读状态 `unread/read/archived` 与采集状态 `queued/processing/ready/link_only/failed` 独立。元数据更新、重试、删除要求 `expectedRevision`，避免覆盖并发编辑。
- 队列最多并行两条，30 秒租约、10 秒续租，启动后接管过期租约；每条采集最多 90 秒。任务的 generation、lease owner 和 tombstone 共同阻止删除或重试后迟到的 worker 写入。
- 正文通过 parse5 确定性提取：普通 article/main 容器、微信 `js_content` 及作者标题、X 元数据和 Relay 原文媒体、纯文本。X 长文章优先提取 `x-article-body` / `itemprop=articleBody`，不会用短 OG 摘要覆盖实际正文，也不会把外围评论和互动控件当正文；没有文章正文的普通推文才使用摘要。脚本、隐藏元素、导航等噪声不进入正文。不足 80 字降级为仅链接；响应错误保留链接和解释。
- HTTP(S) 仅访问公开标准端口；每次重定向重新验证 URL 和 DNS，最多五跳。复用 web-research 共享网络核心，响应压缩前后均限 5 MiB，保持 TLS 校验。Fake-IP 只允许域名 HTTPS，无代理时可通过本地 TUN 直连且固定校验地址；有显式或系统配置的可信代理时 CONNECT 域名，正常 DNS 仍固定已验证公网 IP。始终校验证书与原域名，不放宽字面量私网 URL、明文 HTTP Fake-IP 或混合私网 DNS。
- 环境变量 `PUDDINGTEAMS_HTTPS_PROXY` 优先于常见代理变量，macOS 无显式配置时读取系统 HTTPS 代理；不修改系统设置，不把代理凭据写入响应。

### 浏览器已保存网页的导入

后台受到微信验证限制时，可在原浏览器等待正文显示后保存为 `.html` / `.htm`，在收藏阅读器选择“导入网页正文”。这是用户主动提供的文件，不由后台控制浏览器，不读取浏览器登录信息。入口始终可用，未取得正文时也直接呈现。

`POST /api/read-later/:id/import-html` 接收 `operationId`、`expectedRevision`、`filename`、`html` 和可选图片 `{path,base64}`。HTML 最大 5 MB；所选图片最多 32 张，单张 5 MB、总计 8 MB，路由 JSON 上限 17 MB。只处理提供的字节，不访问页面 URL、远程图片或文件中引用的本机路径，不运行 HTML 脚本。支持网页内嵌位图，以及网页“全部保存”后用户单独选择的图片；按精确相对路径或无歧义的文件名匹配，优先使用本地 src 而不是原始 data-src。图片缺失会标记提示，正文仍可保存。

提取使用同一微信 `js_content`、标题、作者和 Markdown 转换逻辑；验证页或过短内容拒绝导入。声明链接与收藏地址明确不符时拒绝；微信长链接与短链接无法离线核对时，保留明确的来源对应提示。没有声明链接的文件也明确标注由用户选择确认。

导入事务校验用户归属、revision 与幂等内容哈希；推进 generation、取消待采集任务并建立新正文版本，防止迟到 worker 写回。保留用户标题、笔记、标签和阅读状态；旧正文版本保留，删除与图片生命周期沿用现有规则。失败、越权、并发冲突不提交正文，临时资产会清理。只有提取后的 Markdown 和本地图片进入持久化，原 HTML、脚本和 Cookie 不保留。

正文版本记录 `captureMethod=http|saved_html`，导入版附 `sourceFilename`。阅读器显示“网页导入”；显式送入 Wiki 时冻结相同的来源方式与文件名，不把导入当成服务器实际网络响应，不自动送入知识库。

## 图片与删除

正文和封面图片使用本地相对引用 `assets/<sha256>.<ext>`。图片保存在 `assets/<itemId>/<versionId>/`，通过带收藏、版本和资产 ID 的只读 API 加载；浏览器不按原站 URL 自动请求图片。

每条最多成功保存 16 张图，最多尝试 32 个媒体地址；单图 256 字节至 5 MiB，校验 MIME 与 PNG/JPEG/GIF/WebP/AVIF 签名。同 URL 与同哈希去重。单图失败只形成占位及 warning，正文仍可用；SVG 等未支持格式不作为可执行网页内容保存。重抓失败保留上次可读正文、图片及其出处元数据，成功才切换到新版本。

删除先提交 tombstone、取消任务、删除自有正文版本，再清理自有资产。API 分别返回 `deleted` 与 `cleanupPending`；清理失败由后台重试。历史采集任务与独立整理来源保留。收藏资产不借用 Wiki 全局对象库的生命周期。

## 整理与发布

`ReadLaterPromoter` 只接受当前用户的正文就绪条目和匹配版本，最多 50 篇。服务端校验目标知识库可用性和启用的 pi Wiki 管理员后，冻结来源并调用现有 `WikiCuratorService` 的内部 `sourceIds` 入口。HTTP 不接受任意外部素材 ID。

冻结的 `KnowledgeSource` 使用 `kind=markdown`，包含 `webCapture` 出处（原始/标准化/实际访问 URL、作者、来源、采集时间、收藏及正文版本 ID、提取器版本和正文哈希）与 `assets` 清单。正文、图片、元数据纳入来源 manifest；私人笔记只有明确勾选时才附加，并标记为用户笔记而非原文。

网页附图直接由宿主冻结，不重复走 OCR。Curator 只为页面 frontmatter 实际采纳的来源发布相应图片；页面与图片固定同批、同组，原件先发布，库内路径为 `assets/images/<hash>.<ext>`。图片 bytes/hash/MIME/source 清单分别由 Curator 和 Publisher 校验。来源快照与审核/正式 Wiki 独立于收藏，即使收藏删除仍可核对来源和发布图片。

发起整理不会自动发布。候选查看、来源、逐文件审核、拒绝、退回修订、冲突、版本及发布日志继续使用原有 Wiki 流程。稍后读只提供关联任务和候选深链。

## Agent 收藏工具

普通 Teams pi Manager/业务 Worker 的宿主工具面加入 `read_later_save_url`。工具说明要求明确用户收藏授权，不得自行收藏搜索结果或编造笔记；执行只返回稳定 item/job ID 和稍后读深链，不触发整理或发布。受限 Wiki 整理 Worker 不增加该工具。没有新增会话 JSONL customType，也未把此宿主流程包装成独立 pi 的完整房间能力。

用户已明确取消 GBrain 集成；稍后读当前只负责本地收藏和阅读，以及显式整理到 Wiki 的审核发布闭环，不提供额外下游索引导入。

## API

| 接口 | 用途 |
|---|---|
| `GET/POST /api/read-later` | 搜索、来源/状态筛选、稳定排序分页、计数、创建与去重 |
| `GET/PATCH/DELETE /api/read-later/:id` | 详情/正文/任务/晋升映射、信息与状态编辑、删除 |
| `POST /api/read-later/mark-read` | 全部或选中收藏标为已读；事务内归属校验及选中项 CAS |
| `POST /api/read-later/:id/retry` | CAS 与 operationId 重采集 |
| `POST /api/read-later/:id/import-html` | CAS、内容幂等及离线保存网页正文与所选图片 |
| `GET /api/read-later/jobs[/:id]` | 用户归属采集历史与进度；列表支持 filter/page/limit、全量计数与分页摘要 |
| `GET /api/read-later/:id/versions/:versionId/assets/:assetId` | 限定版本的本地图片，校验内容 hash |
| `POST /api/read-later/promotions` | 受控晋升，冻结后复用 Curator |

所有读取和变更使用宿主当前身份。详情不暴露服务器绝对文件路径、内部 owner/generation/lease 字段；越权资源返回 404。

## 采集任务列表

HTTP 200 仅表示收到页面，不代表取得正文。微信公众号跳转到 `/mp/wappoc_appmsgcaptcha`，或在没有 `js_content` 的页面呈现环境异常及 `js_verify` 时，采集明确返回“微信要求安全验证”，保留链接；验证页的正文、图片和带临时 token 的跳转地址不作为文章保存。失败的重抓保留已有正文、标题、标签和笔记。原文中的验证相关文字不会触发这个判断。后台不会代替用户完成验证，也不保证浏览器验证后后台请求会获得相同访问权限。

阅读器与任务列表共用主题色细圆角进度条。数值表示获取网页、提取正文、归档图片、保存正文这些阶段，不估算剩余时间；10 秒心跳只续租，保留当前阶段和进度。

页面顶部「采集任务 / 刷新 / 收藏链接」使用统一 40px 按钮高度和居中对齐；刷新为 40px 方形图标按钮，并提供独立无障碍名称，不再由图标与文字不同的内容高度决定外框尺寸。

采集任务采用紧凑列表：文章标题、中文状态与查看动作在首行，来源与月日/时分在次行；异常原因只呈现一次，进度仅在排队/运行时显示。可按全部、进行中、异常筛选。任务接口支持 `filter/page/limit`，默认每页 20 条（上限 100），按创建时间和 ID 稳定倒序；SQLite 查询只返回当前页任务及文章摘要，数量统计覆盖当前用户全部任务。弹窗显示总数、当前/总页数及上一页/下一页；切换筛选回到第一页，刷新后页数减少时归到最后有效页，迟到请求不能覆盖新页面。成功但降级为仅链接的任务显示“仅链接”，不把底层 succeeded 误呈现为正文完成。列表 API 增加用户归属的当前文章标题、来源和可用标记；删除收藏后保留历史任务标题，但禁用查看。

## 批量阅读状态

列表“全部已读”作用于当前用户所有未读收藏，包括未加载及当前搜索/来源筛选之外的条目。只修改未读项，不改变归档、已读、已删除或其他用户的收藏；设置 `readAt`、`updatedAt` 并递增 revision，不影响正文、笔记、标签和采集状态。多选栏的“已读”只处理选中项（最多 100 篇），逐项校验归属和 expectedRevision，任何越权/删除/冲突使整个事务失败，不部分成功。已读项重复请求不再增加 revision。

多选栏采用白底（随主题）、紧凑文本动作：数量、已读、整理、取消；整理按钮不再重复显示篇数，仍只接收正文就绪的选中项。

## 验证边界

列表卡片的标题、标签和来源日期在左侧同一文字列中连续排列，右侧封面作为独立列顶端对齐，不参与标题行高度计算。去掉标题区的固定最小高度；短标题或无封面的条目不再为封面预留空白。保留两行标题截断、来源省略、完整标签换行和相对整卡居中的复选框，仅调整布局，不改变阅读状态或收藏数据。

来源筛选框去掉浏览器默认的鼠标焦点外框，仅在 `:focus-visible` 且不是鼠标/触摸操作时显示主题色焦点环；失焦后不保留边框或阴影。2026-10-04 收敛到应用公共焦点策略：由 document 捕获 pointerdown、keydown 与焦点切换并标记离散控件，不再维护来源框的局部 React 状态；目标知识库 select 同样受此策略约束。不在选择后强制 blur，以保留键盘连续筛选能力。

收藏列表使用带圆角边框的紧凑卡片，复选框相对整张卡片垂直居中。标题在左、已保存的本地缩略图在右，标题下方以小标签显示全部标签，底部显示来源域名和日期；没有标签时显示“未分类”。收藏与信息编辑输入框支持中英文逗号、分号分隔，自动去除首尾空白、空项和重复标签，输入时显示标签预览；标签中的空格保留。列表 API 只返回当前正文版本的缩略图 `versionId/assetId/alt`，不返回外站图片地址或服务器路径；图片仍走归属和版本校验的资产 API，无本地图的条目不显示空白缩略图。

新增确定性测试、真实 Curator/审核/Publisher 集成测试、完整服务器测试、web typecheck/lint/build、独立发行安装与页面检查分别记录在 `.pudding/handoff/2026-09-30-read-later-migration/实施验收.md`。微信/X 的 fixture 不等于所有真实站点都可抓取；登录墙和反爬限制会保留链接并显示错误。正式 UI 与产品验收仍由用户确认。
